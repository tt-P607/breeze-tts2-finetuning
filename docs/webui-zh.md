# 本地 LoRA 训练 WebUI

使用 Gradio，把数据准备、预处理、训练、续训、损失曲线和 LoRA GGUF 导出放在同一页。页面和命令行使用同一个训练工作流，不另写一套训练器。

## 启动

本机已有环境时，双击仓库里的 `start_webui.bat`。地址是 **http://127.0.0.1:7862/**。不开放公网，也不自动开始训练；打开页面不会加载底模到显卡。

其他环境在本仓库目录运行：

```powershell
uv pip install --python <已有训练环境的Python> -r requirements-webui.txt
<已有训练环境的Python> webui.py --workspace-root <工作区目录> --open
```

本机不需要重新安装依赖。默认复用工作区中的以下资源，可在页面的“环境路径”中修改：

| 资源 | 相对工作区的路径 |
| --- | --- |
| 训练 Python | `training-preparation/.venv/Scripts/python.exe` |
| 原始训练底模 | `training-preparation/base-model` |
| 微调源码 | `breeze-tts2-finetuning` |
| LoRA 转换脚本 | `Breeze-TTS-2.cpp/scripts/convert_lora_to_gguf.py` |
| 转换依赖 | `training-preparation/gguf-export/deps` |

训练使用原始 PyTorch 底模，不能填推理用的 Q8 / F16 GGUF。此页面只提供现有 LoRA 路径；上游其他训练方式仍按原文档使用。

## 1. 准备数据

在“数据准备”填入本地路径，可以是：

- JSONL：每行 `{"audio":"音频路径","text":"准确台词"}`，相对音频路径以清单所在目录为准。
- GPT-SoVITS `.list`：每行 `音频路径|说话人|语言|准确台词`。
- 音频目录：每个音频有同名 `.txt` 或 `.lab`。只有当整个文件名确实就是准确台词时，才选择“整个文件名就是台词”。

支持 WAV、FLAC、MP3、OGG；读取后显示条数、总时长、采样率、声道和标注，点击一行可以试听。缺少台词、重复音频或文件不存在会报出具体位置，不会悄悄丢掉。

填角色或风格名、可选形态和新批次名，再点“复制数据，建立新训练批次”。音频复制到新批次的 `audio`，标注写入 `train.jsonl`、`validation.jsonl`，来源记录写入 `dataset.json`。不改原音频，不覆盖已有批次。

角色放在 `角色模型/<角色>/<可选形态>/训练批次/<批次>`，风格放在 `风格模型/<风格>/训练批次/<批次>`。默认随机留出约 5% 验证数据：它们只用于衡量效果，不参与训练。随后自动选择这个批次，仍未开始训练。

## 2. 训练

默认 Rank 16、Alpha 32、学习率 0.0001、梯度累积 4，实际训练到 **250 步，每 25 步保存**。内部学习率调度预留至 300 步，在 250 步保存后暂停，保留进一步续训的空间。这些是本机已有训练的起点，不保证其他数据量也适用。

1. 修改参数后先点“保存本批次参数”。已有训练输出的批次是历史记录，不允许改写。
2. 点“检查配置（不训练）”，查看路径和将执行的命令；不会调用 GPU。这不是质量检查，也不能保证显存够用。
3. 新批次可以点“预处理 → 训练 → 导出”。已有缓存时点“开始训练”；也可单独预处理。

同一 WebUI 一次只运行一个任务。训练前自己在管理页面停止占显存的 TTS / 翻唱服务，页面不会停止其他项目。沿用统一工作流的磁盘、显存监测；不会因为接近某个显存数字就机械中止。

下方显示当前阶段、步数、显存、GPU 使用率、磁盘剩余量、逐步训练损失和检查点验证损失。日志在批次中保存为 `统一WebUI控制台.log`、`统一训练.log`，资源记录为 `统一资源监测.jsonl`。

“保存并暂停”在当前训练步结束后验证并保存完整检查点，再退出；预处理期间会等当前阶段结束。“强制停止本任务”会终止本页面启动的进程树，当前未完成的步骤不会保存。关闭页面不会停止训练，关闭启动窗口前请先暂停任务。

## 3. 续训和导出

在“续训与导出”刷新并选择检查点。完整检查点包含 LoRA 权重、优化器、调度器、随机状态和训练记录。默认训练停在 250 步后，可将续训目标改成 275 或 300，沿原始调度继续，不改写原始配方。

续训目标必须高于检查点步数，不超过原调度上限。修改 Rank、学习率或调度等属于新实验，应建立新批次。已经按用户要求删除优化器状态的旧检查点会标为“仅导出权重”，不能恢复训练；达到原调度终点的批次也不能在原批次中延长。

任一含 `adapter.safetensors` 的检查点都可单独导出 LoRA GGUF。输出路径已有文件时拒绝覆盖。导出的是小型 LoRA 适配器，不会合成或复制完整底模；现有 C++ 后端可按路径加载。

## 命令行

在本仓库目录使用同一个入口：

```powershell
..\training-preparation\.venv\Scripts\python.exe -m training.workflow.cli --config "角色模型/角色/训练批次/批次/training-config.json" --dry-run
```

配置内相对路径从工作区根目录解析。去掉 `--dry-run` 才执行。`--stage prepare|train|export|all` 选择阶段；`--resume <检查点>` 加 `--stop-after-step 275` 可续训到新的停点。`--export-checkpoint <检查点> --export-output <文件.gguf>` 可以临时选择导出目标，不修改历史配置。

历史配置无需搬动，页面会扫描角色模型、风格模型和数据集中的 `training-config.json`。`historical_only=true` 的特殊旧实验只展示配方，不直接执行。

## 验证范围

页面导入、复制、批次配置、任务调度、日志、暂停、续训参数和导出参数由 CPU 测试覆盖。模型训练和音质沿用现有训练器；启动页面或“检查配置”不代表已经做过新一轮 GPU 训练。
